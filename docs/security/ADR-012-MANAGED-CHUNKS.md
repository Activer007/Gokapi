# ADR-012：普通分片按上传用户隔离

SEC-032；基线 3d93cdb，私密防御合同 6314e6d。2026-10-28；单进程、个人 VPS / 可信小团队。

## 决策

普通上传的外部 UUID 是用户空间内的标识，不再直接作为全局临时文件名。服务端根据当前认证用户 ID 和规范化 UUID 生成有界长度的 managed 存储标识。浏览器接收、API 接收、同步/异步完成和出错清理使用相同映射。File Request 保留服务端随机预约 ID 及既有预约校验，不能进入 managed 存储空间。

内部标识采用 `managed.<userId>.<sha256>`，只有严格匹配该格式的存储 ID 保留点号；外部普通 UUID 总要先规范化、哈希并绑定当前用户。旧版 UUID 规范化不可能生成点号文件名，因此新命名不会误认既有无所有者分片。文件仍以 chunk- 开头，现有 GC 无需变更。

不按 API Key 绑定：同用户的长期 Key、临时 Key 和浏览器 session 可以继续同一上传；权限仍由现有入口读取当前用户/Key 后判断。当前不存在“代他人完成未完成分片”的公开授权接口，因此管理员也只能完成其自己的普通上传。已完成文件的跨所有者权限保持原样。

不同用户使用相同外部 UUID 时，add 可以成功创建各自独立的分片，但绝不能追加/删除/消费其他用户或请求的分片。缺少自己分片的 complete 在异步排队前返回既有 400 / UnspecifiedError。原始 RED 对全局 ID 的拒绝预期私密保留；新合同同时检查独立创建和目标完整性，不能只删除负例断言。

存储标识不作为 SSE 的客户端 ChunkId；客户端继续收到原 UUID。进程内状态表以 UserId + ChunkId 为键，防止不同用户使用同 UUID 时互相覆盖或抑制进度。不新增数据库表、所有者注册表、租户、ACL、依赖或前端协议。

## 兼容、迁移与回滚

公开路由、字段、成功响应、UI/WASM、已完成文件名和 SQLite/Redis schema 不变。UUID 继续沿用现有规范化规则；新增用户域，且内部文件名不能通过外部 UUID 绕过再次映射。未更改已完成内容加密、S3 或本地驱动。

旧版本的普通临时分片没有可靠所有者，禁止首次访问时盲目认领。升级前完成在途上传；升级后剩余普通上传需重新上传，新代码不会读取旧全局分片。File Request 的原有内存预约仍会在进程重启后丢失，客户端需重新预约并上传。无需迁移已完成文件，不执行真实文件迁移或删除脚本。

临时文件继续以 chunk- 开头，沿用原有超过 24 小时的清理策略；本项不扩大删除范围或修改保留时间。先在隔离目录验证。回滚代码后已完成文件仍可读，新格式的未完成分片不被旧上传流程续传，需要重新上传；旧授权行为也随回滚恢复，因此回滚期间应限制上传入口。当前尚未部署，无生产数据迁移。

## 验证与边界

必须验证普通 API/浏览器接收、同用户换 Key、不同用户同 UUID、File Request 域隔离、缺失/错误完成的同步和异步拒绝、错误清理不触碰其他域、客户端进度 UUID 与用户隔离、临时文件清理兼容，并复用已完成的 File Request 预约回归。生产修复须取得 GREEN 与三组全量和相关 race 后才能发布。

不承诺同一用户对同一上传同时追加/完成的事务语义、多进程所有权协议、总上传资源额度、真实 Redis/S3 环境认证。正常通过授权的任务允许完成，遵从 M2 修订目标。
