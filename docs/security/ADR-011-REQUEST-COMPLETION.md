# ADR-011：File Request 完成时校验预约作用域

SEC-032；基线 a65ecfef82f50e374bc0d3978d5e4dfac239db69，2026-10-28。单进程、可信小团队，公开 File Request 上传者不可信。

## 决策

File Request 的 add 和 complete 都要求该请求仍拥有该 UUID 的有效预约。新增只读 IsValid 查询，不延长或消费预约；complete 在任何同步处理、错误清理或异步排队之前执行检查。预约过期秒采用 Expiry > now，与取消预约一致；SetUploading 在相同边界拒绝续期。

不授权时返回既有 HTTP 400 / InvalidChunkReservation，保留原始分片、文件元数据和其他请求预约。合法完成继续由现有流程创建归属于请求所有者的文件并 SetComplete。UUID 不是跨请求的授权凭据，即使两个请求属于同一用户，也不能互相消费分片。

复用现有内存预约表、互斥锁和当前 Key/请求校验，不新增数据库表、权限系统或上传协议。此项只补 File Request 的完成入口，普通管理上传身份绑定不由本项测试证明。

## 兼容和回滚

不改路由、请求字段、响应成功结构、已生成页面/WASM、用户 ID、文件命名、SQLite/Redis schema 或本地/S3 驱动。公开上传先 reserve、再 add、最后 complete 的现有流程不变。完成前预约已丢失/过期时，现在必须重新预约并重新上传；进程重启原本即会丢失内存预约，不能把历史孤立分片当成已授权上传。未增加孤立分片删除或迁移脚本。

采用单进程停止/启动升级；在途公开上传应先完成或由客户端重试，已有已完成文件无需迁移。回滚代码并重启可读取原数据，但会恢复较宽的完成行为；若必须回滚，应限制公开 File Request 访问，不能把回滚称为保留此项防护。当前未部署，仅操作隔离合成文件。

## 边界和证据

授权通过后正在执行的单个任务允许完成，不尝试抢占传输。完整取消/完成/追加竞态、重复完成原子性、文件总额/数量预算、普通管理分片所有者绑定、真实 Redis/S3 与浏览器不由本项证明；不建设分布式任务协议。

私密实际 API 合同在临时 SQLite/miniredis 和本地文件上创建上传，验证合法 add/complete、跨请求/跨所有者/普通分片拒绝、撤销 Key、过期请求，以及异步拒绝不排队。公开回归覆盖预约范围/到期边界与同步、异步入口守卫。详细复现保留私密；本地命令、初次 RED 和最终结果见 TEST-REPORT。
