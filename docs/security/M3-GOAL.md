## 只做三项

1. **最小启动恢复**：复用现有ledger、RecoveryBatch、chunk session与私有spool；在接新上传和常规GC前，
   有界核对可识别的遗留状态。只自动清理未Claim且已过期的自有输入，或已确认提交后的自有私有暂存；
   清理确认后才释放预留，不对canonical作同类删除。
2. **保守处理不确定状态**：已Claim但未能确认提交、发布不明确、无法证明归属的whole工作或canonical文件，保额、保文件，
   不猜测补提交、退款或删除。输出不含密钥/Token/分享URL的本地诊断摘要，并提供一页人工恢复流程。
3. **完成验收与交接**：冻结SHA执行下面三类进程崩溃验收，更新基线、看板、威胁模型及测试报告；
   将完成、延期、NOT_RUN逐项对账，给出备份/回滚/启动检查步骤后结束本阶段。

## 只保留三类崩溃验收

| 退出窗口 | 最低可证明结果 |
| --- | --- |
| Reserve/写入后、Claim前 | 重启只续用已确认输入或清理已过期自有输入；未确认清理不得退款 |
| Claim/PrepareTarget后、Commit前，含发布不明确 | 不补造metadata、不删canonical、不退款；列出人工处置项 |
| Commit后、暂存清理或HTTP回复前 | 已提交文件只保留一份且内容正确；已知自有暂存清理幂等，不明确whole残留保守保留 |

参考验收采用SQLite+本地驱动、临时目录及真实子进程退出/重启，小payload做哈希读回。
保留SQLite/Redis和本地/S3架构；Redis复用已有模型/事务回归，不据此声称Redis持久化或S3崩溃原子性已验证。
进程崩溃不等于磁盘断电；不新建日志协议、通用恢复框架或自动补提交系统。

## 收口Gate与工作节奏

- 不误删已发布数据，不重复发布，不重复退款；可确认清理的预留最终可释放，不确定状态需人工处理。
- 人工流程固定为：停进程→备份DB/DataDir/加密配置→离线核对→处理已确认对象→重启验证；不在生产数据试错。
- 开发期只跑受影响的恢复合同；最终代码一次必要CI，并发修改跑相关race。只有变更/失败才补所需验证。
- 未改流式路径不重复1–2GiB性能、浏览器、完整真实后端或镜像矩阵；旧证据按原SHA保留，未执行明确NOT_RUN。
- 不部署、不推镜像、不写上游。收口只证明本文件冻结范围，不宣称初版广义M3或全部安全待办已完成。
