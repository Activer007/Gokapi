# ADR-022：普通删除失败保留原管理锚点

状态：ACCEPTED，2026-10-29；SEC-040-A；原基线8c399317，当前主线c434e0997e61d368dd9c4705d3ba4e10a0a01882。

## 不变量及RED

确认源已删除/确实不存在，或完整检查证明内容仍被其他分享引用后，才退休该分享的metadata及归属hotlink。
probe、引用枚举或删除失败/未知时保留已过期管理锚点及其原逻辑计量，不重新授予下载权限。
确认前不退休；COMMIT/EXEC结果未知时不报告完成，下一轮复读核对。已确认物理删除后退休失败不能承诺原字节仍在。
不存在与无权限/超时必须分开；不删除符号链接、目录、路径越界或未知归属对象。
原SEC040失败夹具真实执行loopback DELETE并失败，对象仍在而metadata丢失：8c业务RED12.079s；同步c434后仍RED12.290s。

## 最小方案

复用原metadata的ID/owner/locator/到期意图，不增任务表/schema。新增checked有界ID枚举、完整bucket+hash引用读取、
条件退休；单行读取复用M3安全reader。SQLite同事务、Redis WATCH/CAS检查快照，并只清理仍归属本文件的hotlink。
持现有blob锁完成重读、探测、引用检查、删除和退休；物理I/O不跨数据库事务。删除接受实际context。
本地操作由os.OpenRoot锚定显式受信DataDir，兼容配置根symlink；对象本身必须是普通文件，拒绝对象symlink/目录。
引用扫描检查每个local名称，不只检查删除候选；拒绝分隔符、路径别名、ADS、设备名、尾点/空格、非ASCII等不规范名称。
正常大写E2E单组件保留；两个local locator仅大小写不同时保守报unknown并保留锚点，不猜其物理身份或误作shared退休。
S3 key按bucket+key精确字节身份，不做本地路径归一化；删除后HEAD核对当前对象不存在，未知留待重试。
完整枚举最多16384 ID；批次30s、单项5s。枚举不完整即停止；单项失败记录首错并继续其余ID各一次，不busy-loop。
deadline覆盖DB/S3及本地操作间的检查，不承诺中断已经阻塞的OS文件系统调用；配置DataDir仍按受信本地存储假设。
CleanUpContext返回确认退休的Deleted/Shared/Missing计数及不透明error；提交未知不增加完成计数。
wrapper失败时只记固定pending摘要并跳过辅助维护，周期调度仍保留；下一次GC/重启可重试，不建立新任务框架。

## 尚未关闭的边界

040-A条件退休不能撤回已发生的物理删除。定时/取消/恢复/参数写者之间的完整状态门禁及明确API/UI反馈由040-B闭合，
不能据本PR宣称取消竞态已解决。041旧locator持久候选、孤儿扫描、全站GC索引不属于本PR。
单进程与可信DataDir假设不变；既有公开/FR/session/API授权不变，不承诺备份或S3历史版本安全擦除。

## 兼容和回滚

公开DeleteFile/CleanUp入口保留，失败不再丢管理记录；保留记录期间用量继续保守计入，确认退休后才自然减少。
无数据或密钥迁移；失败记录可能比旧版多保留，这是恢复能力所必需。回滚前停机备份DB/DataDir/加密配置，
暂停清理、核对失败记录；旧版本可能再吞错并丢锚点，不能用回退代替失败处置。已成功删除内容只能从备份恢复。
不规范/歧义legacy locator不会自动改名或删除，应停机备份后人工核对全部引用；checked读取错误不能当作数据不存在。
批次超限/超时会明确失败并保留未确认记录，不保证一次回收任意规模数据；公开删除返回值仍是受理语义，040-B补明确反馈。
