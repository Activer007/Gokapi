# ADR-022：普通删除失败保留原管理锚点

状态：IMPLEMENTING，2026-10-29；SEC-040-A，基线8c39931733be853dd68d11ad5b193088c4d928d5。

## 不变量及RED

确认源已删除/确实不存在，或完整检查证明内容仍被其他分享引用后，才退休该分享的metadata及归属hotlink。
probe、引用枚举、删除或退休失败/未知不能假装完成；保留已过期管理锚点及其原逻辑计量，不重新授予下载权限。
不存在与无权限/超时必须分开；不删除符号链接、目录、路径越界或未知归属对象。
最新基线原SEC040失败夹具真实执行loopback DELETE并失败，对象仍在而metadata丢失：业务RED，exit1/12.079s。

## 最小方案

复用原metadata的ID/owner/locator/到期意图，不增任务表/schema。新增checked有界ID枚举、完整bucket+hash引用读取、
条件退休；单行读取复用M3安全reader。SQLite同事务、Redis WATCH/CAS检查快照，并只清理仍归属本文件的hotlink。
持现有blob锁完成重读、探测、引用检查、删除和退休；物理I/O不跨数据库事务。删除接受实际context。
本地单组件locator/DataDir/普通文件检查；S3删除后核对当前对象不存在，未知留待重试。
批次/单项有deadline，日志只输出固定摘要，不打印底层异常/路径/对象key。失败下一次GC或重启重试。
失败时保守结束本轮GC，延后辅助维护以避免legacy读取掩盖失败；周期调度仍保留，不建立常驻新任务框架。

## 尚未关闭的边界

040-A条件退休不能撤回已发生的物理删除。定时/取消/恢复/参数写者之间的完整状态门禁及明确API/UI反馈由040-B闭合，
不能据本PR宣称取消竞态已解决。041旧locator持久候选、孤儿扫描、全站GC索引不属于本PR。
单进程与可信DataDir假设不变；既有公开/FR/session/API授权不变，不承诺备份或S3历史版本安全擦除。

## 兼容和回滚

公开DeleteFile/CleanUp入口保留，失败不再丢管理记录；保留记录期间用量继续保守计入，确认退休后才自然减少。
无数据或密钥迁移；失败记录可能比旧版多保留，这是恢复能力所必需。回滚前停机备份DB/DataDir/加密配置，
暂停清理、核对失败记录；旧版本可能再吞错并丢锚点，不能用回退代替失败处置。已成功删除内容只能从备份恢复。
