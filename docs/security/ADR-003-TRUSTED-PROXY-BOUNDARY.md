# ADR-003：代理身份与来源 IP 的共同信任边界

日期：2026-10-28；SEC-013；工作基线 `7200526486d7a4b317043fe7056e6d279e1c92f3`。仅修改 Activer007/SupaShare；尚未部署。

## 不变量与决策

只有直接 TCP 连接的 RemoteAddr 命中部署者配置的可信 IP/CIDR，才能提供 Header Auth 用户名或来源 IP。请求自称的 XFF/CF 地址不能改变这个判断。复用既有 `GOKAPI_TRUSTED_PROXIES`，不增加第二套默认宽松规则；默认仍仅127.0.0.1，需要IPv6回环时显式配置::1。配置在启动时由 logging.Init 读取。

Header Auth 仍使用原用户名映射及 OnlyRegisteredUsers 设置；连接不受信或用户名头缺失/重复时在查库、自动创建用户之前拒绝。不改变session/API Key/OIDC/File Request/公开下载的认证方式；这不是稳定OIDC身份迁移。

Cloudflare模式仍须显式开启。CF-Connecting-IP仅在直接peer可信且值为单一合法IP时生效。XFF多行按顺序合并，从右向左跨过可信代理，取首个不可信地址；若整个链均可信，取最左端。遇到正在检查的空/畸形跳点，直接退回peer，不跳过、不改信X-Real-IP。X-Real-IP仅在无XFF时使用，亦须单一合法IP。被采信的IP采用规范表示。

Docker自动探测网段不再默认授信：`GOKAPI_DISABLE_DOCKER_TRUSTED_PROXY`默认改为true。否则，同网桥所有容器可能都成为身份代理，这与默认收紧管理边界不一致。保留显式false作为旧行为的兼容选择；它会信任探测到的整个网段，包含身份头，不能称为最小权限。优先固定反代IP或使用仅含可信代理的专用网络/CIDR。不能用0.0.0.0/0或::/0解决登录问题。

## 部署与迁移

1. 停止外部写入并备份配置；确认实际直接连接地址，配置精确代理IP/CIDR。Docker升级前设置显式代理地址，不能依赖原自动信任。源站端口限制为本机/专用网络或防火墙仅允许反代。
2. 身份代理必须先认证，并覆盖用户传入的身份头；边缘代理应清除/规范化来源IP头。可信peer意味着信任它提供这些值，服务端不能区分它转发的用户伪造值与其自行生成值。
3. Cloudflare直连源站时，显式配置并维护Cloudflare官方来源网段，限制源站入口。若经本地反代，配置该反代的直接地址，且反代只能从受验证的Cloudflare入口保留CF头；普通公网请求必须移除该头。不要把“开启Cloudflare选项”等同认证所有来源。当前不联网自动更新IP表。
4. 在隔离副本验证可信代理登录/回调、直连拒绝、来源IP及上传下载。变更来源IP可能改变限流分组；畸形链退回代理IP属于保守退化，需修正代理头而非放宽信任。反代未配置将导致Header登录被拒绝，应在维护窗口处理。

无数据库schema、哈希、用户ID、文件或加密格式迁移。回滚代码无需恢复数据；但会恢复旧的宽松来源处理。回滚前必须从网络层只允许已认证代理访问源站，不应通过恢复公网直连处理配置错误。显式旧Docker选项仅用于已隔离、所有成员均可信的兼容环境。

## 验证范围

隔离反例覆盖不可信/可信peer、CF重复或非法值、XFF多层/多行/畸形/全可信链、IPv6、明确Docker地址/CIDR、Header用户名重复、注册限制和无副作用拒绝。真实回环HTTP检查相同请求仅在peer明确配置后通过。Docker模式测试验证配置解析，不等于容器网络和非root卷实测；后者归SEC-011。新增测试不宣称外部部署账户接管、浏览器利用或新的CVE。
