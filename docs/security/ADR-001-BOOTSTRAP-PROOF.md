# ADR-001: 本地文件提供一次初始化证明

状态：SEC-010 实施；基线 `0b72099243e091eec4eb053154c46ce3dbf2fd7a`。

## 不变量与选择

首次安装和重新配置均须持有进程生成的随机证明，未授权请求不能保存配置或建立超级管理员。复用现有 HTTP Basic 对话框，固定用户名 setup；使用密码学随机的32字符证明，存储在配置目录中 CreateTemp 创建的0600文件。只打印文件路径，不打印密码、不使用秘密 URL、不增加持久身份字段。日志读取权限本身不再等价于初始化权限；能读取进程配置目录的账户属于部署者信任边界。

原生监听127.0.0.1；Docker内部保留通配监听以支持端口映射，宿主发布必须绑定回环或受信 HTTPS 代理。通过SSH隧道保留远程VPS安装体验。现有配置直接跳过首次安装；--reconfigure 使用独立的新证明。

只有配置保存成功才原子撤销证明。保存路径互斥、再次检查完成状态，拒绝已通过认证但排队中的第二次提交；验证失败允许重试。正常结束删除证明文件，崩溃后旧文件不被重用。配置写入原有的多文件持久化语义未改变，崩溃一致性和备份恢复继续由SEC-063处理。

使用 Go 标准库 [CrossOriginProtection](https://pkg.go.dev/net/http@go1.26.0#CrossOriginProtection) 拒绝跨站浏览器写请求；配置保存只接受POST。标准库允许没有Origin/Fetch Metadata的非浏览器客户端，这些请求仍必须提供证明。TLS反代须保留外部Host，不能靠未经验证的转发头改变来源判断。

## 兼容、迁移和回滚

无schema、用户密码哈希或文件存储迁移。已安装实例正常启动不读取证明。首次安装自动化须从本地文件读取新证明并用Basic Header提交POST；旧的匿名提交不再兼容。Docker --user 需对配置目录可写，不改变镜像默认USER，不递归chown旧卷。Linux模式位是本轮验证范围；Windows ACL和实际Docker运行留在环境Gate中。

回滚SEC-010代码提交不需转换数据，但会重新开放原始首次安装边界；仅在隔离网络、已有有效配置和备份条件下回滚。不要将回滚后的无配置实例直接发布到公网。未删除的过期证明文件可由部署者核实路径后清理，不能用通配删除配置目录。

## 验证

隔离安装模拟覆盖匿名完整配置提交被拒、有效证明安装成功、验证失败重试、成功后重放拒绝、已有配置跳过、重新配置成功；证明文件权限/轮换/失效、双模式认证、跨站来源、POST限制和并发过期提交有专门测试。原始RED和每次回归结果均保留在TEST-REPORT；Docker容器体验不能仅由监听地址单元测试认定通过。
