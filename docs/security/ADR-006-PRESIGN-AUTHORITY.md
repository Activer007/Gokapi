# ADR-006：管理 presign 的当前授权与一次性消费

状态：已实施，本地回归通过；SEC-021；基线d599aabfbc7f52aa06a14a006348992adc94247a，2026-10-28。最终PR/CI见TEST-REPORT。

## 合同与证据

M2要求管理下载能力在消费时仍受当前授权约束。现有API在签发时检查Download位和文件读取权，内存presign只保存文件集合及30秒有效期；消费入口要求登录，但不重新关联签发Key/用户，读取和删除grant分开进行。隔离RED证明此行为与M2的新合同不一致。持有合法短期capability的转交本身不自动构成未知漏洞；本项明确选择更严格的管理授权语义，不能把公开分享链接混为一谈。

## 决策

- 内存grant保留签发用户ID和Key ID，URL仍只有随机grant ID。每次消费复用API凭据校验，要求Key存在、未过期、有Download位、属于签发者且不是File Request Key；签发者仍有效。
- 重新读取当前下载者，并对每个文件同时检查签发者和下载者的ReadFile策略。允许具有读取权的其他管理员使用有效grant；不把grant强制绑定同一浏览器或同一用户。不具备对象读取权的登录者不能靠转交管理grant获得读取权。
- 过期/待删/缺失资源继续通过storage.GetFile拒绝。全部检查通过后原子Consume；并发只有一名消费者成功。被拒绝的调用者不能消耗合法用户的grant。领取后传输失败不会恢复grant，客户端重新签发，保持原有一次性尝试语义。
- 不改变公开分享/密码下载、File Request上传能力、物理删除、加密实现或S3驱动。复用已有错误结构：无登录401，失效管理grant400；已授权成功仍200或现有存储响应。

## 兼容与回滚

保持公开路径、签发参数、downloadUrl字段、30秒最长寿命、单文件/ZIP流程和生成页面/WASM。变化是签发Key提前过期或撤销、对象授权变化、无读取权的其他登录者不再能消费该管理grant。UI正常使用同一登录用户的短期API Key，签发后立即下载，流程不变；单次HTTP请求通常携带当前会话，代理认证/禁用内置认证仍由既有requireLogin决定身份。

无SQLite/Redis schema或用户ID变化；新增字段仅在进程内。正常升级重启本来就会清空所有未消费grant，无需数据库迁移或备份转换。无签发身份的内存grant默认拒绝。滚动切换到另一进程仍可能使grant不可用，与原有进程内设计一致；不借本项引入共享存储。

回滚本PR并重启即可，数据无需转换；会恢复旧管理capability语义。不能以回滚为理由更改已完成的SEC-020/021权限交集与使用记录修复。现阶段尚未部署，没有真实数据操作。

## 有意保留的边界

授权检查与数据库权限修改不是跨provider事务：撤销完成后开始的新消费检查会拒绝；已通过检查并开始输出的传输不被抢占。单次领取本身是进程内原子操作。文件元数据可能在检查与打开之间变化，仍需单独验证在途变更；不宣称线性化整个下载或物理删除生命周期。S3已签发外部短期URL的有效性由存储服务决定，真实S3/代理网络与浏览器本项NOT_RUN。

测试从真实API签发及可信认证context后的handler消费验证当前权限；匿名requireLogin另测，不把context注入称为完整浏览器登录。SQLite/miniredis覆盖权限变化、所有者变化、ZIP成员、永久/临时Key、缺失主体、拒绝不消耗、顺序重放及并发单次消费。存储级测试补充到期秒边界及32个并发领取者。
