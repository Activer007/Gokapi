# ADR-013：M3 上传预算与兼容草案

状态：PROPOSED，2026-10-28；基线 e38b03f。用户已确认保留 MaxSize 单文件语义、另增累计限制；其余账本/默认值/迁移仍为待实现方案，事务/入口尚未实施。适用单进程个人VPS/小团队，保留 Go、SQLite/Redis、本地/S3、现有UI/WASM/API/CLI。

## 问题与不变量

[现状调查](M3-UPLOAD-SEMANTICS.md) 显示单文件/请求体/瞬时磁盘检查不是共享预算。所有新写入必须先在持久层原子检验 `used + reserved + requested <= limit`，非法负值/溢出失败关闭。拒绝不能改写其他上传数据；完成同一上传只能计费一次。取消/失败清理完成后才能释放对应物理预留。仅纯计算或进程锁不证明原子准入。

## 建议计量合同

1. 用户逻辑用量：按每条 metadata 的当前 UserId 计 SizeBytes 和文件数，共享 SHA1 不抵扣；File Request 按 UploadRequestId另聚合，即使文件随后转移所有者，也不能假定它仍归请求创建者。E2E按服务端可验证的上传密文长度计，RealSize只展示。过期/待删但仍存在的metadata继续计量，直到删除/所有者变更与账本原子提交；不改旧 Populate 展示语义。
2. 实例物理容量：DataDir/TMPDIR 如属不同文件系统分别计预算/最低余量。记录在途声明和处理放大（multipart spill、原chunk、加密新副本），不按逻辑总量猜测实际空闲。只有实际发现可复用blob且不再需要暂存时才释放物理额度；S3也需要本地暂存预算。现有 MIN_FREE_SPACE 继续作为安全余量。
3. 请求各自有限文件数、单文件长度、新累计字节和在途槽；用户在途槽跨其所有Key共用，避免换Key扩大额度；实例有全局HTTP正文/处理槽。沿用 MaxSize 每文件、新增累计限制的建议不静默重解释旧数据。有限默认值与旧请求显式迁移在接入 PR 前确定，并保证有余量时1–2GB文件可上传。

## 最小预约协议

持久记录稳定上传键（owner/request/client UUID）、首次声明字节、状态、期限和最终metadata ID。状态 `reserved → uploading → committed`，失败/取消为aborted，到期为expired。终态保留有界幂等回执，不能立即删除后允许重放。重试同键同声明返回原预约；不同声明拒绝。完成先原子领取一次，上传写入不能与完成/取消相互污染。

普通客户端首块隐式预约以保持现有接口。旧 File Request reserve 没有长度参数，先占数量/在途槽，首块再原子绑定字节；可增可选声明字段，但旧客户端路径必须继续测试。已有非重叠并行块是兼容要求，不能通过任意禁止乱序写入规避完整性验证。

SQLite用事务同时验证用量/预留并写入预约；Redis用Lua对相同约束原子检查写入，数值必须保持精确（限制并拒绝超出安全整数域或使用精确整数算法），不能借浮点转换绕过上限。metadata保存与预约commit要在各provider同一原子操作完成；替换/复制/转移/删除也需更新逻辑账本。Go锁只协调本进程文件I/O，不能代替数据库事务。

取消/超时/失败由幂等终止路径清理已登记暂存后释放额度；删除失败保留可重试状态和额度。进程重启先在停止接收上传时对账预约/metadata/受管理暂存，恢复已提交回执、重试安全清理；不能先清空账本再发现文件仍占容量。物理blob删除遵守引用/失败保护，不能借配额升级直接试删真实数据。过期扫描使用有限批次，状态/临时文件/回执均有期限和数量上限。

## 流式处理和验收

统一入口最终按实收file part字节与首次声明/偏移核对，允许无Content-Length但仍受有界正文/字段/协议开销限制；预算在读取大正文前/过程中生效，真实Context断线释放I/O/等待。保留支持旧multipart字段顺序的方案，不能只假设file在最后。有限并发处理槽覆盖同步和异步完成，不能为每次重放无限起协程。完整文件不读入内存。

必需回归：10/50抢1额；声明谎报/未知长度/极大offset/重复重叠块/重复完成；数量/累计/磁盘不足；断线/取消/超时/过期/重启；加密/S3本地暂存放大/共享blob；普通与FileRequest/API/CLI；1–2GB正确性、吞吐、内存与暂存峰值。每项先RED后GREEN；变更服务端校验只能依据新合同，并保留等效防线。

## 兼容、迁移与回滚 Gate

本草案和语义PR不改schema、metadata、物理文件或准入。后续schema PR必须先给SQLite/Redis独立备份、升级锁、现有metadata用量重建、旧未完成上传处理、幂等重跑与隔离恢复测试，再提高版本。回滚使用配套旧库/配置快照；不得让旧程序继续写新账本后声称配额有效。新版本写入后优先向前恢复，避免旧快照遗漏新文件。未验证迁移不进入发布。

后续PR不得把此草案当作已批准的默认额度或已运行的恢复机制；实现与测试完成后逐项更新状态。分布式配额/多租户/新权限引擎不属于本阶段。
