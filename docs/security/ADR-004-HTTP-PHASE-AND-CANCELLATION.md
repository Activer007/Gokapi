# ADR-004：HTTP 阶段超时与限流取消

2026-10-28；SEC-014；基线 `138642c72ea481a2b63d2ed5e1aac071de34a01d`。仅本 fork，未部署。

## 决策

主服务和安装服务均设置5秒 ReadHeaderTimeout、60秒 IdleTimeout。完整请求头必须及时送达，空闲keep-alive连接不能沿用数小时的传输预算。主服务正文读取仍为2小时、响应写入仍为12小时；安装服务读写仍为2分钟。没有用全局短TimeoutHandler包裹上传、下载或SSE。代理应及时转发完整头；该限制与用户填表时间无关。

五类限流等待改用当前请求Context并返回错误；安装认证/AWS测试、登录、API认证、下载密码、无效ID重定向等调用点在取消或等待失败时停止后续处理。内部Go函数签名改变，公开HTTP API不变，令牌速率和burst不变。取消不会授予认证或跳过限流。已经开始的存储操作、密码计算或后台任务不由此自动回滚；本项不声称所有应用工作都可取消。

清理任务的sync.Once只负责启动一个协程，然后返回。以前在Once回调中永久运行ticker会使后续Get启动的协程阻塞在Once；现在每个store只有一个应用生命周期清理循环，保留30分钟清理周期和12小时闲置回收策略。此修复不为来源IP数量设置新的全局内存配额。

## 兼容与回滚

没有数据库、文件格式、密码、OIDC或E2E迁移。长正文、文件响应和已建立SSE不受5秒头期限及60秒空闲连接期限截断；实际持续时间仍受原读写/SSE期限及反代限制。异常慢的头或闲置连接会较早关闭，HTTP客户端应重新建立连接。没有新增所有管理handler的统一执行截止时间；本项区分的是头/空闲阶段与正文/响应传输阶段。

回滚代码无需恢复数据，但会恢复慢头占用、不可取消的限流等待及清理协程增长。若回滚，应先在反代限制请求头时间和空闲连接并限制源站访问；不能据此声称反代修复了应用协程问题。

## 验证边界

真实TCP慢头测试分别覆盖主服务和首次安装服务；真实HTTP断线取消覆盖等待处理器。五类限流都有未取消正例、耗尽后等待和取消退出断言；登录、API和安装证明在取消后不继续授予身份。重复128次查询的协程数有界。

真实API流式上传16,896,000字节合成文件（超过fixture的10MiB内存阈值），正文中途暂停6秒；匿名下载长度与SHA-256一致，原SSE连接在暂停后仍收到事件。该测试只接触临时副本，不是100GB、真实S3或浏览器性能验收。既有三组和OIDC/权限回归继续执行；新测试不启动全局异步GC，物理删除可靠性仍属于SEC-040。
