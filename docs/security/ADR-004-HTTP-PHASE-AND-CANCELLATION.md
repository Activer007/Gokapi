# ADR-004：HTTP 阶段超时与限流取消

2026-10-28；SEC-014；基线 `138642c72ea481a2b63d2ed5e1aac071de34a01d`。仅本 fork，未部署。

## 决策

主服务和安装服务均设置5秒 ReadHeaderTimeout、60秒 IdleTimeout。完整请求头必须及时送达，空闲keep-alive连接不能沿用数小时的传输预算。主服务正文读取仍为2小时、响应写入仍为12小时；安装服务读写仍为2分钟。没有用全局短TimeoutHandler包裹上传、下载或SSE。代理应及时转发完整头；该限制与用户填表时间无关。

五类限流等待改用当前请求Context并返回错误；安装认证/AWS测试、登录、API认证、下载密码、无效ID重定向等调用点在取消或等待失败时停止后续处理。内部Go函数签名改变，公开HTTP API不变，令牌速率和burst不变。取消不会授予认证或跳过限流。已经开始的存储操作、密码计算或后台任务不由此自动回滚；本项不声称所有应用工作都可取消。

清理任务的sync.Once只负责启动一个协程，然后返回。以前在Once回调中永久运行ticker会使后续Get启动的协程阻塞在Once；现在每个store只有一个应用生命周期清理循环，保留30分钟清理周期和12小时闲置回收策略。此修复不为来源IP数量设置新的全局内存配额。

## 兼容与回滚

没有数据库、文件格式、密码、OIDC或E2E迁移。长正文、文件响应和已建立SSE不受5秒头期限及60秒空闲连接期限截断；实际持续时间仍受原读写/SSE期限及反代限制。异常慢的头或闲置连接会较早关闭，HTTP客户端应重新建立连接。没有新增所有管理handler的统一执行截止时间；本项区分的是头/空闲阶段与正文/响应传输阶段。

回滚代码无需恢复数据，但会恢复慢头占用、不可取消的限流等待及清理协程增长。若回滚，应先在反代限制请求头时间和空闲连接并限制源站访问；不能据此声称反代修复了应用协程问题。

## 验证边界

真实TCP慢头测试分别覆盖主服务和首次安装服务；真实HTTP断线取消覆盖等待处理器。五类限流都有未取消正例、耗尽后等待和取消退出断言；登录、API和安装证明在取消后不继续授予身份。重复128次查询的协程数有界。

真实API流式上传16,896,000字节合成文件（超过fixture的10MiB内存阈值），正文中途暂停6秒；匿名下载长度与SHA-256一致，原SSE连接在暂停后仍收到事件。该测试只接触临时副本，不是100GB、真实S3或浏览器性能验收。既有三组和OIDC/权限回归继续执行；新测试不启动全局异步GC，物理删除可靠性仍属于SEC-040。

## M1补充：管理路由预算（基线863fdb5）

以上是PR #6的阶段记录。本次补齐M1第5项：管理路由从分发时起具有30秒网络读写及Context预算；头阶段仍另限5秒。采用Go ResponseController设置请求读/响应写deadline，并把同一截止时间传给原请求Context。处理器在原协程执行，不另建后台处理器、不额外缓存整个响应。依据[Go1.26的ResponseController语义](https://pkg.go.dev/net/http@go1.26.0#ResponseController)：写deadline后的少量已缓冲数据可能成功，不能把期限理解为事务提交截止或保证返回特定HTTP错误码；网络超时可能表现为连接/流关闭。

默认所有已注册管理页面（含登录、改密、用户/Key/日志、OAuth登录回调、下载密码表单）和非传输API适用短预算。文件下载/预签名下载/文件名URL/两类hotlink、网页chunk上传、SSE、WASM和静态/自定义资源保持原2小时读、12小时写及既有SSE期限。API路由表明确标记单文件/ZIP下载、files/add、chunk/add/complete、File Request chunk/add/complete；资源分类和实际API路由匹配共用同一matcher，不替代任何权限判断。新API默认短预算，新增传输入口必须明确声明并补矩阵测试。mux最终仍正常分发以保留PathValue，不能直接调用查出的handler跳过变量绑定。

OAuth回调Exchange和UserInfo改用请求Context；过期/取消后不继续错误重定向或用户登录。协议参数、Cookie、issuer/sub/email关联及密码算法不变。Provider发现仍是启动流程，不属于入站管理请求预算。本项没有改安装服务的既有2分钟读写预算或E2E协议。

期限会释放网络I/O、限流等待及支持Context的IdP请求；**不强制终止已启动且不响应Context的CPU、数据库、存储操作，不保证超时的写操作未提交**。客户端遇超时须先查询状态再决定重试，不能盲目重放用户创建、文件修改等非幂等操作。该边界通过同步执行避免新增被抛弃的处理协程；全局并发/内存额度和存储事务仍属后续SEC-030/040。本次无schema或物理文件生命周期变化。

验证包含真实应用/login完整头后的慢正文、正常管理请求、HTTP/1及HTTP/2慢读、阻塞响应写、同一keep-alive连接从管理转文件、全部API预算分类、Token/UserInfo两个阶段的IdP断线。16,896,000字节上传的中途暂停由历史6秒提高到31秒，SSE同连接与下载摘要继续验证；既有HTTP/TLS反代回调作为正例。测试writer不支持网络deadline时仍有Context；生产标准HTTP/1和HTTP/2 writer的deadline用真实连接证明。

兼容影响：异常慢管理调用可能更早断开，反代不应自动重试非幂等管理请求；文件传输预算不缩短。回滚本次Go代码无需数据转换，但恢复小时级管理I/O和不可取消的IdP请求；仍须保持代理网络限制和备份。此处的完成仅为M1部署边界，不等同发布签名、真实生产冷恢复或全局资源配额完成。
